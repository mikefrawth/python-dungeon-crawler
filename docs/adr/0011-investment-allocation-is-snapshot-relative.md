# Investment Allocation tracks spend against a per-pass snapshot, not universal baseline 0

ADR-0010 established that creation, leveling, and NPC/monster generation share one parameterized spend-tracking mechanism, but the first implementation (`CharacterCreation`) computed points spent as `raw_value − 0` and floored `undo` at `0`. That only matches "points spent this pass" when the pass starts from baseline — true for creation, false for leveling, where a character already carries prior investment before the pass begins.

We decided spend, remaining, and the undo floor are all measured relative to a **per-attribute snapshot taken at the start of the allocation pass**, not universal baseline 0. Player character creation is the special case where that snapshot happens to be all zero (matching ADR-0009's "no dump-stat" floor); leveling's snapshot is whatever the character already has. Once spend-tracking is snapshot-relative, creation and leveling have no remaining behavioral divergence — both are one class, `InvestmentAllocation` (renamed from `CharacterCreation`, which named only its first use case and didn't hold once leveling was in scope), with named classmethod factories per pass type (`for_player_creation`, later `for_level_up`, `for_npc_generation`) rather than a base class with subclasses per pass type.

Only `for_player_creation` is implemented now — `Character` and leveling don't exist yet, so a `for_level_up` factory would have no caller. The snapshot-relative design is what makes adding it later a new factory method, not a rewrite of `spend`/`undo`/`points_remaining`.
