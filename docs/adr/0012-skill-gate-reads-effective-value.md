# Skill's minimum-requirement gate reads Effective Value, not raw attribute

`docs/NOTES_character_progression.md` says every skill has "a minimum attribute requirement to use at all (hard gate, not soft)" but never says whether that requirement is compared against the attribute's raw invested score or its Effective Value. Both are defensible: raw is what a content designer intuitively sets a threshold against ("needs 5 invested Might"), while Effective Value is what every other consumer of an attribute — scaling, skill checks, derived combat stats — already reads.

We decided the gate reads Effective Value, matching CONTEXT.md's Effective Value entry: "the number skills, feats, and derived stats actually read. Never the raw attribute." Treating the minimum-requirement gate as an exception — the one place a skill still looks at raw — would mean two different lenses on the same attribute depending on which part of `Skill` you're reading, with no signal in the code for why. One rule, no exceptions, is easier to reason about and matches the glossary's own wording.

Consequence: `minimum_requirement` values are expressed in Effective Value units, not raw attribute points. A designer setting `minimum_requirement=3` is asking for an Effective Value of 3 (roughly 9 raw points under the default `sqrt` curve, not 3 raw points) — content tooling that authors skill data should convert from a raw-points intent to an Effective Value threshold, not pass raw numbers straight through. This also means retuning the curve's coefficient shifts every skill's effective gating difficulty even if `minimum_requirement` itself never changes.
